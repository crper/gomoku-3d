## 0. 数据基石回顾（工程已确认的语义）

回放功能**不需要任何新数据结构**，完全建立在既有 `GameState.history: HistoryEntry[]` 之上：

- 落 N 手后 `history.length === N`。
- `history[k]` = **第 k 手落完后的棋盘快照**（含 k 个棋子）；`history[0]` = 空盘。
- `game` 本身 = 最终态（N 子）。
- 「渲染第 k 手后的盘面」(k ∈ [0, N])：
  - k = 0 → `history[0].board`（空盘）
  - 1 ≤ k ≤ N-1 → `history[k].board`
  - k = N → `game.board`
- 第 j 手（j ∈ [1, N]）的落点坐标 = `history[j-1].board` 与「第 j 手后盘面」的逐格 diff（唯一变化的格）；执子方 = `history[j-1].currentPlayer`。
- 建议工程在进入回放时**一次性预计算** `moves: ReplayMove[]`（`{ index, x, y, player }`，长度 N），后续回放与导出共用，避免每步重复 diff 225 格。

## 1. 功能范围与设计原则

### 1.1 范围

| 功能 | 说明 |
|---|---|
| 回放 | 逐步前进 / 后退 / 跳转任意手数 / 播放-暂停 / 播放速度调节 / 进度条拖动 |
| 导出 | SGF（主格式）/ JSON（第二格式）/ TXT（纯文本坐标，可选），文件命名可编辑，保存到本地 |
| 反馈 | 每步落子状态清晰可读；导出成功 toast；空局禁用并提示 |

### 1.2 核心原则：回放 = 只读观察模式

**进入回放后，禁用一切改变对局状态的实时操作**：落子（棋盘点击/悬停预览）、悔棋、重开（重开改为「先退出回放再确认」，见 §3.5）。退出回放后，棋盘与控件恢复到进入前的实时对局状态，**对局数据零改动**。

**为什么这样设计**：
1. **避免状态冲突**：若回放中允许落子，会产生「从第 k 手分叉」的变体树语义，`history` 是线性数组，无法表达分叉；强行支持会污染引擎不可变状态、且与 AI 调度（不可改动）冲突。
2. **心智模型简单**：玩家清楚地知道「我现在在看录像，不是在下棋」，无需理解复杂的分支规则。
3. **实现安全**：回放态只是一个「渲染用的视图指针 currentStep」，实时对局的 `game` 对象原封不动，退出即还原，天然无副作用。

**AI 思考中的处理**：若 AI 正在思考（现有 AI 思考覆盖层可见），「回放」入口临时禁用（disabled + tooltip「AI 思考中」），避免回放期间 AI 异步落子导致 N 变化。AI 落子完成后自动恢复可用。这是纯 UI 门控，不触碰 `ai.ts`。

### 1.3 触发时机

- `moveCount > 0` 即可进入回放（含对局进行中与已结束）。`moveCount === 0` 时「回放」按钮 disabled。
- 对局结束（胜/负/平）后是回放的主场景，但**不强制**——进行中也可回看前几手（此时进入回放会先暂停实时交互，AI 门控见上）。
- 入口：底部控制条新增「回放」按钮（图标建议：⏮/📽 播放胶片类），与既有 悔棋/重开/静音/2D-3D 并列，见 §3。

## 2. 回放状态机

### 2.1 状态定义

```
ReplayMode = 'idle' | 'replaying-paused' | 'replaying-playing'
```

| 状态 | 含义 |
|---|---|
| `idle` | 未在回放，实时对局正常交互（当前应用的默认状态） |
| `replaying-paused` | 回放中，暂停；可拖进度条 / 单步 / 播放 |
| `replaying-playing` | 回放中，自动播放；每 `speedMs` 毫秒自动 `stepForward` |

### 2.2 核心变量

| 变量 | 类型 | 范围/默认 | 说明 |
|---|---|---|---|
| `currentStep` | number | 0..N，进入回放时初始 = 0 | 当前展示「第 currentStep 手后的盘面」；0 = 空盘 |
| `isPlaying` | boolean | false | 派生：`mode === 'replaying-playing'` |
| `speedMs` | number | 800（= 1×） | 自动播放每步间隔；速度档 0.5×=1600ms、1×=800ms、2×=400ms、4×=200ms |
| `N` | number | 进入回放时快照 `game.moveCount` | 总手数，回放期间视为常量（AI 门控保证不变） |
| `moves` | ReplayMove[] | 进入时预计算 | 见 §0 |

### 2.3 操作语义

| 操作 | 前置条件 | 语义 |
|---|---|---|
| `enterReplay()` | `moveCount > 0` 且 AI 非思考中 | idle → replaying-paused；`currentStep = 0`；预计算 `moves` |
| `stepForward()` | `currentStep < N` | `currentStep += 1`；到达 N 时若在播放则自动 `pause()` |
| `stepBack()` | `currentStep > 0` | `currentStep -= 1`；后退**总是先 pause()**（用户回看意图明确） |
| `goTo(k)` | `0 ≤ k ≤ N` | `currentStep = k`；播放中拖动 = 拖动期间暂停，松手后维持暂停（避免拖着拖着又自己跑） |
| `play()` | `currentStep < N` | → replaying-playing；启动 `setInterval(stepForward, speedMs)`。若 `currentStep === N` 则先 `goTo(0)` 再播放（「重播」语义） |
| `pause()` | playing | → replaying-paused；清定时器 |
| `togglePlay()` | — | playing ? pause() : play()；绑定空格键与播放按钮 |
| `setSpeed(ms)` | — | 更新 `speedMs`；播放中立即以新间隔重建定时器 |
| `exitReplay()` | 回放中 | → idle；清定时器；棋盘恢复渲染实时 `game` 最终态 |

### 2.4 边界规则

- `currentStep === 0`：「上一手」按钮 disabled；再按无效。
- `currentStep === N`：「下一手」按钮 disabled；自动播放到达 N 时停止并回到 paused，播放按钮变为「重播 ↺」形态。
- 进度条拖动 = `goTo(k)`，k 按最近整数手吸附（进度条步进 = 1 手，不允许半手）。
- 回放中若 `winLine` 存在：**仅当 `currentStep === N` 且对局有胜者时**渲染胜利连线与流光；中间步不显示（历史上该时刻还没赢）。
- 退出方式：显式「退出回放」按钮、Esc 键；不提供「点击棋盘退出」（易误触）。

## 3. 回放控件布局（含响应式）

### 3.1 总体方案：回放浮层条（Replay Bar）替换底部控制条

进入回放时，**现有底部控制条整体切换为「回放控制条」**（同一位置、同一容器高度，交叉淡入 150ms）。理由：
- 避免两排控件同屏导致认知过载与移动端空间不足；
- 「悔棋/重开」在回放中本就该禁用，隐藏比 disabled 更干净；
- 「静音」「2D/3D 切换」这两个与回放兼容的功能**保留在回放条右端**（视角切换在回放中很有用——2D 看局面、3D 看动效）。

### 3.2 回放条内容（桌面端，单行）

```
[退出 ✕] | [⏮ 首手] [◀ 上一手] [▶/⏸ 播放] [下一手 ▶] [末手 ⏭] | ━━━●━━━━ 12/34 | [速度 1× ▾] | [🔊] [2D/3D]
```

- **进度条**：可拖动 slider（复用现有 `ui/slider.tsx`），min=0 max=N step=1；右侧文本「`currentStep / N`」等宽数字（`tabular-nums`），拖动中实时更新盘面（scrubbing）。
- **播放/暂停**：单个切换按钮，playing 时显示 ⏸；`currentStep===N` 时显示 ↺（重播）。
- **首手/末手**（⏮/⏭）= `goTo(0)` / `goTo(N)`，低成本高收益，建议保留；空间不足时（移动端）可省。
- **速度调节**：下拉/循环点按按钮，档位 `0.5× / 1× / 2× / 4×`，映射间隔 `1600 / 800 / 400 / 200 ms`。默认 1×。显示当前档位文本。
- **退出**：最左（或最右）「✕ 退出回放」，视觉上与其他控件分组分隔。

### 3.3 当前手信息展示（满足「清晰查看每步落子状态变化」）

在棋盘上方（桌面：棋盘容器左上角悬浮小卡片；移动端：回放条上方一行）展示：

```
第 12 手 · ● 黑（玩家） · (7, 8)
```

- 内容：手数 `currentStep`、执子方（●黑/○白 + 颜色圆点）、「玩家/电脑」标签（按当前先手设置映射：默认黑=玩家、白=电脑；若先手设置为 AI 执黑则反转）、交叉点坐标 `(x, y)`。
- `currentStep === 0` 时显示「开局 · 空盘」。
- 数据来源：`moves[currentStep - 1]`。
- 每次 step 变化时该卡片内容更新并轻微闪烁强调（reduced-motion 下仅变文本）。
- 盘面配合：第 `currentStep` 手的棋子以**入场弹跳动画**落下（复用既有落子动效）+ **最后一手脉冲标记**定位在该子上——盘面与文字双通道传达「这一步发生了什么」。

### 3.4 响应式

| 断点 | 布局 |
|---|---|
| `lg`（≥1024，双栏） | 回放条单行铺满棋盘下方原底栏位置；当前手信息卡悬浮棋盘左上 |
| `<lg`（单栏/移动） | 回放条两行：第一行 = 进度条 + 步数；第二行 = ✕ / ◀ / ▶播放 / ▶ / 速度 / 2D-3D（静音可收进速度旁或省略，首手/末手省略）。当前手信息置于回放条上方单行。按钮触控目标 ≥ 44×44px |

### 3.5 进入/退出的入口与视觉态

- 入口：底部控制条「回放」按钮，`moveCount>0` 且 AI 非思考中可用；对局结束时该按钮加高亮描边/微光（引导用户复盘），reduced-motion 下为静态高亮色。
- 回放中的全局视觉态：右侧边栏（难度/先手/战绩/成就）整体降透明度至 ~50% 并 `pointer-events: none`，顶部或棋盘角落显示「回放模式」badge——让用户一眼知道当前处于只读态。
- 退出：✕ 按钮 / Esc；退出后底栏交叉淡回实时控制条，棋盘立即渲染实时 `game` 最终态（无逐子重演）。

## 4. 导出流程 UX

### 4.1 触发入口

- 底部控制条新增「导出棋谱」按钮（图标：💾/下载箭头），**实时态与回放态均可见可用**（回放条右端也放一个入口，复盘后顺手导出是高频路径）。
- `moveCount === 0` 时 disabled，tooltip/长按提示「暂无棋谱可导出」。
- 点击打开**模态对话框**（桌面居中 modal，移动端底部抽屉样式；复用现有 card/button/label 组件手写，不引依赖）。

### 4.2 对话框内容

```
┌─ 导出棋谱 ─────────────────────┐
│ 格式                            │
│  (•) SGF  — 通用棋谱格式，可导入   │
│      绝大多数围棋/五子棋/连珠软件   │
│  ( ) JSON — 结构化数据，含元信息，  │
│      便于程序读取与二次开发        │
│  ( ) TXT  — 纯文本坐标列表，人类   │
│      可读，便于粘贴分享           │
│                                 │
│ 文件名                          │
│  [gomoku-20260408-153012   ] .sgf│
│                                 │
│         [取消]      [导出]       │
└─────────────────────────────────┘
```

- **格式选择**（单选，默认 SGF）：
  - **SGF（推荐/默认）**：Smart Game Format，围棋/五子棋/连珠软件的事实标准。
  - **JSON**：含完整元数据 + 着法列表，面向程序消费。
  - **TXT**（可选实现，优先级最低）：`1. 黑 (7,7)` 每行一手，便于聊天分享。
  - **设计决策记录：PGN 不用于五子棋。** PGN（Portable Game Notation）是国际象棋专用格式，其着法记法（棋子字母+格号+吃子/易位语义）无法表达五子棋落子，业界五子棋/连珠均使用 SGF。故本功能**以 SGF/JSON 替代 PGN**，UI 中不出现 PGN 选项。
- **文件命名**：文本输入框，默认值 `gomoku-YYYYMMDD-HHMMSS`（本地时间，如 `gomoku-20260408-153012`）；扩展名按所选格式**自动追加且不可编辑**（输入框右侧灰字后缀 `.sgf` / `.json` / `.txt`，切换格式时实时联动）。输入清空时导出按钮 disabled；非法文件名字符（`/ \ : * ? " < > |`）实时替换为 `-`。

### 4.3 导出执行与反馈

- 点击「导出」：前端生成字符串 → `new Blob([text], { type })` → 创建 `a[download=文件名]` → 触发点击 → `URL.revokeObjectURL`。MIME：SGF `application/x-go-sgf`，JSON `application/json`，TXT `text/plain`（均 `;charset=utf-8`）。
- **成功反馈**：关闭对话框 + toast（复用现有 `ui/toast.tsx`）：「✅ 已导出 gomoku-20260408-153012.sgf」，3 秒自动消失。
- **失败/边界**：
  - `moveCount === 0`：入口 disabled（第一道防线）；若状态竞争导致对话框内 N 变 0，导出按钮 disabled 并提示「空对局无法导出」。
  - Blob/下载异常（极罕见）：toast 错误态「导出失败，请重试」。
  - 对局进行中导出：允许，导出截至当前的着法，SGF `RE` 写 `?`（未知结果，见 §5）。

## 5. SGF 格式规格（工程实现精确规则）

### 5.1 文件结构

```
(;GM[4]FF[4]CA[UTF-8]SZ[15]AP[Gomoku3D:1.0]DT[2026-04-08]PB[玩家]PW[电脑]RE[B+W];B[hh];W[ii];B[hg])
```

逐属性说明：

| 属性 | 值 | 说明 |
|---|---|---|
| `GM` | `4` | 游戏类型。SGF 标准中 GM[4] = Gomoku+Renju（GM[1] 是围棋）。若工程更看重与任务书对齐/围棋软件兼容性，可用 `GM[1]`，两者均可被主流软件打开；**默认建议 GM[4]，在代码常量处留注释** |
| `FF` | `4` | SGF 版本 4 |
| `CA` | `UTF-8` | 字符编码（PB/PW 含中文，必须声明） |
| `SZ` | `15` | 棋盘 15×15 |
| `AP` | `Gomoku3D:1.0` | 生成应用标识（可选） |
| `DT` | `YYYY-MM-DD` | 导出日期 |
| `PB` / `PW` | 可读名 | 按先手设置映射：人类方=「玩家」，AI 方=「电脑」。默认（人类执黑）→ `PB[玩家]PW[电脑]`；若 AI 先手执黑则反转 |
| `RE` | 见下 | 结果：黑胜=`B+W`，白胜=`W+W`，平局=`0`，对局未结束=`?` |

### 5.2 着法序列

- 格式：`;B[xy];W[xy]...`，黑白严格交替，黑先（第 1 手执子方以 `moves[0].player` 为准）。
- 坐标编码：字母 a–o（0→a … 14→o），**先 x 后 y**：`String.fromCharCode(97 + x) + String.fromCharCode(97 + y)`。例：(5,2) → `fc`；(7,7) 天元 → `hh`。
- **无 PASS**：五子棋不虚着，序列为纯落子，不出现 `B[]`/`W[]` 空着法。
- 整个文件单行输出即可（SGF 对换行不敏感）；结尾 `)` 闭合。

### 5.3 示例（前 3 手：黑(7,7)、白(8,8)、黑(7,6)，黑最终获胜）

```
(;GM[4]FF[4]CA[UTF-8]SZ[15]AP[Gomoku3D:1.0]DT[2026-04-08]PB[玩家]PW[电脑]RE[B+W];B[hh];W[ii];B[hg])
```

### 5.4 JSON 格式规格

```json
{
  "meta": {
    "app": "Gomoku3D",
    "boardSize": 15,
    "blackName": "玩家",
    "whiteName": "电脑",
    "result": "B+W",
    "date": "2026-04-08T15:30:12+08:00",
    "moveCount": 34
  },
  "moves": [
    { "index": 1, "x": 7, "y": 7, "player": 1, "label": "黑·玩家" },
    { "index": 2, "x": 8, "y": 8, "player": 2, "label": "白·电脑" }
  ]
}
```

- `index` 从 1 开始；`player` 沿用引擎语义 1=黑 2=白；`result` 与 SGF `RE` 同值域；`date` 用 ISO 8601 含时区。
- `JSON.stringify(data, null, 2)` 两空格缩进输出。

### 5.5 TXT 格式（若实现）

```
五子棋棋谱 2026-04-08 15:30  黑：玩家  白：电脑  结果：黑胜
1. 黑 (7,7)
2. 白 (8,8)
3. 黑 (7,6)
```

| **`src/components/ui/toast.tsx`** | 复用，导出成功/失败提示 |
| **不动** | `src/lib/gomoku/ai.ts`（含调度）、`engine.ts`（history 已够用，只读消费） |

回放动效关键点（对齐 `design/fx-spec.md`）：单步前进时**只有新增的那颗子**播放入场弹跳；`goTo(k)` 大跨度跳转时不逐子重演（直接渲染目标盘面，仅目标手的子做一次入场 + 脉冲），避免拖动进度条时动画风暴。

## 7. 可访问性与降级

- **reduced-motion**（`prefers-reduced-motion: reduce`，沿用全局机制）：
  - 落子入场弹跳 → 直接出现；最后一手脉冲 → 静态高亮环；胜利流光 → 静态描边（均已是既有降级，回放路径必须走同一套开关）。
  - 回放条自身动画（底栏交叉淡入、播放按钮跳动、进度条流动光效、当前手信息闪烁、回放按钮引导微光）→ 全部降级为无动画的即时切换/静态样式。
- **键盘可达**：
  - `←` = 上一手，`→` = 下一手，`Space` = 播放/暂停，`Esc` = 退出回放，`Home`/`End` = 首手/末手（可选）。
  - 仅在回放模式挂载监听；焦点位于文本输入（导出文件名）时不拦截。
  - 所有按钮可 Tab 聚焦，有可见 focus ring（沿用现有 shadcn 风格）。
- **屏幕阅读器**：进度条 slider 带 `aria-label="回放进度"`、`aria-valuetext="第 12 手，共 34 手"`；当前手信息卡为 `aria-live="polite"`；播放按钮 `aria-pressed`；导出对话框 focus trap + `role="dialog"`。
- **色彩无关**：执子方同时用文字（黑/白）+ 圆点图形表达，不单靠颜色。
